# Sprint 25 Verification Inventory

## Scope

[`verification-inventory.json`](verification-inventory.json) is a generated, deterministic registry
of CodingMage's Rust public API declarations and stable `codingmage.*` error codes. Each item records
its source path, line, kind, stable inventory identity, applicable verification categories, and exact
test-symbol mappings where the current suite provides them.

The closed categories are positive behavior, negative behavior, exact boundaries, malformed input,
unknown fields, and repeatability. An absent mapping is retained in the top-level `coverage_gaps`
array with status `uncovered`; it is never inferred as passing from a crate-wide test command.

## Generation And Validation

```text
python3 scripts/verification_inventory.py --write
python3 scripts/verification_inventory.py
python3 -m unittest tests.test_verification_inventory -v
```

At the current 2026-09-27 source refresh, the registry contains 1,679 source surfaces and 811
explicit category gaps. The immediately prior native UI artifact contained 1,675 surfaces and
811 gaps; this refresh adds the bounded work-plan label and its limit, plus exact command-preview
surfaces with their tests. The older original artifact contained 1,111 surfaces and 868 gaps; the
generator also found new campaign mission,
runtime receipt/recipe/support, and native UI visual-token surfaces in that earlier refresh. No files
exist under the generator's `schemas/*.json` input, so this refresh contains no JSON schema
entry. Line-number-based IDs
also change when declarations move, accounting for much of the entry churn. The gap count is
intentionally nonzero and is reported by the generator after every run. The validator rejects
stale generated bytes, duplicate or
missing identities, missing source paths, missing test paths, and test references whose symbols no
longer exist. Mutation tests remove a mapping, replace a source path, and replace a test symbol to
prove that gaps remain explicit and structural drift fails closed.

Mappings are a keyword-based index of candidate test symbols within the same crate, not proof
that an individual test exercises a particular declaration. An independent source-bound check is
still needed before treating a category as covered. The generated inventory is a work queue,
not a source-bound schema or product acceptance record.

## Stable applicability correction, 2026-10-01

An independent cumulative review of the native Work plan catalogue found
that the inventory's moving source-neighborhood heuristic dropped the public
`failure_box` entry's boundary category when unrelated preceding UI text
changed. The original artifact and finding remain available at their exact
commit and review record. Decision 0055 gives this panel a stable, explicit
category declaration keyed by source path, declaration kind and name. Boundary
applicability keeps minimum-window and long-text behavior in the work queue;
the crate-wide candidate test mappings still do not prove coverage.

The corrected source-consistent artifact has 1,770 items and 825 explicit
gaps. Against the last independently PASS-reviewed ancestor, the normalized
item and gap multisets are identical and 21 raw line-derived IDs move. The
focused inventory regression varies unrelated neighboring words and checks
that this panel retains boundary applicability. Other heuristic entries
remain subject to later review rather than a silent category-model rewrite.
