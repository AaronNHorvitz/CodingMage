# Sprint 25 Verification Inventory

## Scope

[`verification-inventory.json`](verification-inventory.json) is a generated, deterministic registry
of CodingMage's Rust public API declarations and stable `codingmage.*` error codes. Each item records
its source path, line, kind, stable inventory identity, applicable verification categories, and exact
test-symbol mappings where the current suite provides them.

The closed categories are positive behavior, negative behavior, exact boundaries, malformed input,
unknown fields, and repeatability. An absent mapping is retained in the top-level `coverage_gaps`
array with status `uncovered`; it is never inferred as passing from a crate-wide test command.

## Generation And Validation

```text
python3 scripts/verification_inventory.py --write
python3 scripts/verification_inventory.py
python3 -m unittest tests.test_verification_inventory -v
```

The current registry contains 1,109 source surfaces and 866 explicit category gaps. Its gap count is
intentionally nonzero and is
reported by the generator after every run. The validator rejects stale generated bytes, duplicate or
missing identities, missing source paths, missing test paths, and test references whose symbols no
longer exist. Mutation tests remove a mapping, replace a source path, and replace a test symbol to
prove that gaps remain explicit and structural drift fails closed.

## Status Boundary

Sub-tasks `25.2.1.1` and `25.2.1.2` are complete because the public surface is inventoried and every
applicable category is either mapped to exact evidence or explicitly marked uncovered. Parent Task
`25.2.1` remains open: the registry is a coverage work queue, not proof that every gap has been
filled. Existing focused tests and broader scenario evidence remain valid, but neither substitutes
for an absent per-surface category mapping.
